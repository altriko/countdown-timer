# Learning Log
## Countdown Timer — Phase 1: Types, Interfaces & Functions

## Questions & Learning Points

---

### 1. Why use `type` with `|` instead of `{}`?

`type TimerState = "idle" | "running" | "paused" | "done"` uses a **union type** — the `|` means "this OR that". It restricts a variable to only one of those exact string values.

Using `{}` is object syntax — it's for describing an object with properties, not for listing allowed values.

```typescript
let state: TimerState = "running";  // ✅
let state: TimerState = "stopped";  // ❌ TypeScript error at compile time
```

---

### 2. What is `interface`?

An `interface` describes the **shape of an object** — what properties it must have and their types.

```typescript
interface TimerDuration {
    minutes: number;
    seconds: number;
}
```

Any object of type `TimerDuration` must have both `minutes` and `seconds` as numbers. Missing a field or using the wrong type causes a TypeScript error.

---

### 3. `interface` vs `type` — when to use which?

| | Use when... |
|---|---|
| `type` | Defining allowed values, unions, or aliases |
| `interface` | Describing the structure of an object |

For simple object shapes, both work. Convention: use `interface` for objects.

---

### 4. Why `;` in interfaces instead of `,`?

Semicolons are the convention for interfaces (type definitions). Commas are for object literals (actual values).

```typescript
interface TimerDuration { minutes: number; seconds: number; }  // type — semicolons
const myDuration = { minutes: 5, seconds: 30 }                 // value — commas
```

Both `;` and `,` technically work in interfaces, but `;` is the TypeScript standard.

---

### 5. What is `intervalId: number | null`?

`setInterval()` returns a number — an ID for the running interval. You need to store this ID so you can stop it later with `clearInterval(intervalId)`.

- `null` = timer is not running (idle, paused, done)
- `number` = timer is running, ID is stored here

```
Start  → setInterval(...) → store ID in intervalId
Pause  → clearInterval(intervalId) → set intervalId to null
Resume → setInterval(...) again → store new ID
Done   → clearInterval(intervalId) → set to null
```

---

### 6. Why do we need both `timer.ts` and `timer.js`?

- `timer.ts` — source file, written by the developer. The browser cannot read TypeScript.
- `timer.js` — compiled output generated by `tsc`. This is what the browser runs.
- `index.html` references `timer.js`, not `timer.ts`.

The flow: **edit `timer.ts` → run `tsc` → `timer.js` is generated → browser reads `timer.js`**

---

### 7. How to run `tsc` automatically?

Use watch mode to avoid running `tsc` manually after every save:

```bash
npx tsc --watch
```

This recompiles `timer.js` automatically every time `timer.ts` is saved.

---

### 8. What does each `tsconfig.json` option mean?

| Option | Meaning |
|---|---|
| `target: "ES2020"` | JavaScript version to compile to |
| `module: "ES2020"` | Module system for import/export (browser-native) |
| `strict: true` | Enables all strict type checks |
| `noImplicitAny: true` | Every variable must have a known type |
| `lib: ["ES2020", "DOM"]` | Tells TypeScript what built-in APIs exist — DOM needed for `document`, `window` etc. |
| `outDir: "./"` | Where to output compiled `.js` files — **removed in this project, see note 14** |
| `sourceMap: true` | Generates `.map` file so DevTools shows `.ts` instead of `.js` when debugging |
| `include: ["timer.ts"]` | Which files to compile |

---

### 9. What is `timer.js.map`?

A source map — a lookup table linking `timer.js` lines back to `timer.ts` lines. The browser never executes it. Used only by DevTools to show original TypeScript code when debugging instead of compiled JavaScript.

---

### 10. CORS error when opening `index.html` directly

Browsers block ES modules loaded from the local filesystem (`file://`). Fix: use a local server.

```bash
npx serve .
```

Then open `http://localhost:3000` instead of the file directly.

### 11. Mental model: why these 11 functions?

Functions are grouped by **responsibility** (separation of concerns):

| Group | Functions | Characteristic |
|---|---|---|
| Pure math | `toSeconds`, `fromSeconds`, `formatDisplay` | Input in, output out — no side effects, easiest to test |
| Logic | `isValidDuration`, `tick` | Decisions and math, still no DOM/audio |
| Side effects | `playAlert`, `render` | Touch Audio API or DOM |
| Event handlers | `handleStart`, `handlePause`, `handleResume`, `handleReset` | Glue — respond to clicks, update state, call render |

**Rule:** One function = one responsibility. If a function does two things, it should be two functions.

### 12. How to debug / test functions without a full UI

Add `console.log` at the bottom of `timer.ts` temporarily:

```typescript
console.log(toSeconds({ minutes: 1, seconds: 30 }))  // expect: 90
```

Then compile and check browser DevTools console (F12 → Console tab).

---

### 13. Returning an object from a function

When a function return type is an interface, return a matching object:

```typescript
function fromSeconds(totalSeconds: number): TimerDuration {
    return {
        minutes: Math.floor(totalSeconds / 60),
        seconds: totalSeconds % 60
    }
}
```

- `Math.floor` — always rounds down (use this, not `Math.round`)
- `%` — modulo operator, gives the remainder after division

---

### 14. `outDir: "./"` causes a compilation error — don't use it

When `outDir` is set to `"./"` (the project root), TypeScript automatically excludes that directory from compilation inputs to avoid re-processing compiled files. Since the source files are also in `"./"`, TypeScript ends up excluding `timer.ts` itself, producing:

```
error TS18003: No inputs were found in config file
```

**Fix:** Remove `outDir` entirely. Without it, TypeScript compiles `timer.js` right next to `timer.ts` — same result, no conflict.

---

### 15. `exports is not defined` error in the browser

This happens when `timer.js` was compiled with an old/wrong `tsconfig.json` (e.g. `module: "nodenext"`) that outputs CommonJS-style code. CommonJS uses `exports` which only exists in Node.js, not the browser.

**Fix:**
1. Ensure `tsconfig.json` has `"module": "ES2020"`
2. Ensure `index.html` loads the script with `type="module"`: `<script type="module" src="timer.js">`
3. Delete the old `timer.js` and recompile with `npx tsc`
